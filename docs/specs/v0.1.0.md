# V0.1.0: Read ABS Time Series

This spec defines the first release of `@ausecon/core` and the `ausecon`
command-line tool. Open it as a GitHub issue with the `ready-for-agent` label
once the repository exists.

---

## Problem Statement

An analyst who works in TypeScript, or in a terminal, has no simple way to get
ABS time series data. The R package `readabs` does this job for R users. A
TypeScript user must find the right spreadsheet on the ABS website and
download it. Then the user must reshape a wide workbook with ten metadata
rows. The user must repeat this work for every release. The ABS Time Series Directory
indexes every series, but its title search depends on exact zero padding, so
naive lookups by table number return nothing.

## Solution

`@ausecon/core` exports one function that reads ABS time series. The caller
names either a catalogue number with optional table numbers, or a list of
series IDs. The function queries the Time Series Directory, downloads the
tables of the latest release, and returns one flat list of observations with
their series metadata.

The `ausecon` tool wraps the same function. `ausecon abs get` writes the
observations to stdout as CSV or JSON, so the user can pipe them into a file,
a spreadsheet, or another program.

## User Stories

1. As an analyst, I want to read every table of a catalogue number,
   so that I get a whole release in one call.
2. As an analyst, I want to read only some tables of a catalogue
   number, so that I avoid downloading tables I do not need.
3. As an analyst, I want to read series by series ID, so that I get
   exactly the series I track across releases.
4. As an analyst, I want series IDs from several catalogue numbers in
   one call, so that I can build a dashboard.
5. As an analyst, I want series ID, date, and value on each
   observation, so that I can join and plot series.
6. As an analyst, I want the series type, unit, and frequency on each
   observation, so that I can filter and label series.
7. As an analyst, I want the table ID, table title, and sheet on each
   observation, so that I can trace a value to its source.
8. As an analyst, I want dates as ISO `YYYY-MM-DD` strings, so that
   time zones never shift a period into the wrong month.
9. As an analyst, I want each period dated on the first day of its
   final month, so that my results match `readabs`.
10. As an analyst, I want an option that returns only series ID,
    date, and value, so that large reads use less memory.
11. As an analyst, I want the latest release by default, so that I
    never read a superseded release by accident.
12. As an analyst, I want to write `6202` or `6202.0`, so that I do
    not have to remember the ABS suffix.
13. As an analyst, I want to write a series ID in lower case, so that
    a copied ID still works.
14. As an analyst, I want to write table number `1` for a table the
    ABS titles `Table 001`, so that zero padding never hides a table.
15. As an analyst, I want to write table numbers such as `5a`, `10C`,
    `X28`, or `021_MTH`, so that I can read every table the ABS publishes.
16. As an analyst, I want table number matching to ignore case, so
    that `x28` finds `Table X28`.
17. As an analyst, I want `APPENDIX 2` and `TABLE 2` treated as
    different tables, so that I get the table I asked for.
18. As an analyst, I want one typed error that lists every unknown
    series ID, so that I can fix them all at once.
19. As an analyst, I want one typed error that lists every unknown
    table number, so that I can correct my request.
20. As an analyst, I want a typed error for an unknown catalogue
    number, so that I can tell a typo from a network fault.
21. As an analyst, I want a typed error for an unexpected spreadsheet
    layout, so that an ABS format change never returns wrong data.
22. As an analyst, I want network and HTTP failures as typed errors,
    so that I can retry or report them.
23. As an analyst, I want to run the library on Node, Bun, or Deno,
    so that I can use it in my existing runtime.
24. As an analyst, I want to provide my own `HttpClient`, so that I
    can add a proxy, retries, or caching.
25. As an analyst, I want each spreadsheet downloaded once per call,
    so that many series from one table stay fast.
26. As an analyst, I want the library to limit concurrent downloads,
    so that it does not overload the ABS servers or trip rate limits.
27. As an analyst, I want `Trend Break` notes left out of the result,
    so that every observation is a real value.
28. As an analyst, I want blank cells left out of the result, so that
    every observation has a numeric value.
29. As an analyst, I want two series with the same description kept
    apart by series ID, so that duplicate descriptions never merge data.
30. As a terminal user, I want `ausecon abs get --catalogue 6345.0`, so that I
    can read a release without writing code.
31. As a terminal user, I want to repeat `--table` to choose several tables, so
    that I can narrow a large catalogue number.
32. As a terminal user, I want to repeat `--series` to read several series IDs,
    so that I can fetch a watch list in one command.
33. As a terminal user, I want CSV on stdout by default, so that
    `ausecon abs get ... > file.csv` gives a clean file.
34. As a terminal user, I want `--format json`, so that I can pipe the result
    into `jq` or a script.
35. As a terminal user, I want `--no-metadata`, so that the output holds only
    series ID, date, and value.
36. As a terminal user, I want errors on stderr with a suggested next step, so
    that a failed command never corrupts my output file.
37. As a terminal user, I want distinct exit codes for usage, not-found,
    and network errors, so that my scripts can react.
38. As a terminal user, I want a usage error when I pass both `--catalogue` and
    `--series`, or neither, so that the tool never guesses what I meant.
39. As a terminal user, I want `--help` to show examples, so that I can learn
    the command without reading the README.
40. As a terminal user, I want shell completions for the new command, so that
    flags complete in my shell.
41. As a terminal user, I want colour off when output is not a terminal or
    `NO_COLOR` is set, so that logs and files stay clean.
42. As a terminal user on Windows, I want the tool to behave as on macOS and Linux,
    so that I can share commands.
43. As a maintainer, I want unit tests that run on recorded fixtures with the

44. As a maintainer, I want a scheduled live test against the real ABS

45. As a maintainer, I want a project User-Agent on every request, so

## Implementation Decisions

These decisions follow the glossary and the decisions in `docs/adr/`.

### Library Interface

- `@ausecon/core` exports one read function. It returns an `Effect` that
  requires the Effect `HttpClient` service. The library never picks a
  platform client, so it stays free of Node, Bun, and Deno APIs.
- The request is a tagged union of two shapes. The catalogue shape has a
  catalogue number and optional table numbers. The series shape has one or
  more series IDs. A request cannot carry both.
- An option turns metadata off. Without metadata, an observation has only
  series ID, date, and value.
- The library decodes request input with the existing `CatalogueNumber`,
  `SeriesId`, and `TableNumber` schemas. Before it decodes, it appends `.0`
  to a four-digit catalogue number and converts a series ID to upper case.
  Invalid input fails with a typed error, never a defect.
- v0.1.0 has no Promise wrapper. Users who do not use Effect run the read with
  `Effect.runPromise` and a fetch-based `HttpClient` layer. The README shows
  this.

### Observation Shape

An observation has these fields, named with glossary terms:

| Field               | Source                                      |
| ------------------- | ------------------------------------------- |
| `tableId`           | Spreadsheet file name without extension     |
| `sheet`             | Worksheet name, such as `Data1`             |
| `tableTitle`        | `TableTitle` from the Time Series Directory |
| `date`              | Column A, as an ISO `YYYY-MM-DD` string     |
| `seriesDescription` | Spreadsheet row 1                           |
| `value`             | Numeric cell                                |
| `seriesType`        | Row `Series Type`                           |
| `dataType`          | Row `Data Type`                             |
| `collectionMonth`   | Row `Collection Month`                      |
| `frequency`         | Row `Frequency`                             |
| `seriesId`          | Row `Series ID`                             |
| `unit`              | Row `Unit`                                  |

These are the 12 `readabs` columns in camelCase. The names follow the
glossary: `table_no` becomes `tableId`, and `series` becomes
`seriesDescription`.

### Time Series Directory Client

- The client sends requests to the documented `abs.gov.au` Time Series
  Directory base URL and follows redirects.
- It reads `NumPages` from page 1 and fetches the other pages. A missing
  `NumPages` means one page. Page fetches run with a small concurrency limit.
- A catalogue request fetches every page of the catalogue number and matches
  table numbers locally, as ADR 0005 records. It never sends `ttitle`.
- A series request sends one `sid` query per series ID. The client collects
  every ID that returns no series and fails once with `SeriesNotFound`.
- The client keeps only rows from the latest `ProductReleaseDate` of each
  table.
- XML parsing uses a runtime-agnostic parser pinned to an exact version. The
  research recommends `fast-xml-parser`. Record the choice in an ADR.

### Table Number Matching

- The table number match extracts table numbers from `TableTitle`. It
  accepts the prefix words `Table`, `Tables`, `TABLE`, `APPENDIX`, and
  `Data cube`, followed by a space or an underscore.
- It reads a table number up to `.`, `:`, a space, or the end of the title.
  It treats an underscore suffix as part of the number only before `.` or `:`.
- A title that lists several numbers, such as `Tables 4, 5 and 6.`, matches
  each number. A range, such as `Tables 01 to 17`, matches each number in the
  range.
- The prefix word is part of the match. `APPENDIX 2` never matches a request
  for table `2`.
- Comparison ignores case and leading zeros.
- A title with no number never matches. v0.1.0 cannot read those tables by
  table number. A user can read them by catalogue number with no tables, or by
  series ID.
- If a requested table number matches no title, the read fails with a
  `TableNotFound` error that lists every unmatched number.

### Spreadsheet Download and Parsing

- The downloader replaces spaces in `TableURL` with `+`, sends the project
  User-Agent, and follows redirects. It downloads each spreadsheet once per
  read, with a concurrency limit.
- v0.1.0 reads `.xlsx` only, with SheetJS from the vendor tarball (ADR 0003).
- The parser skips the sheets `readabs` skips: `Index`, `Inquiries`,
  `Enquiries`, `Contents`, technical notes, notes, and sheet names that contain
  `Table` and a space.
- Each data sheet must have `Series ID` in column A of spreadsheet row 10.
  Otherwise the read fails with a `WorkbookLayoutError` that names the table
  ID and sheet.
- The parser drops rows whose first cell contains `Trend Break` or `see`, and
  blank value cells.
- Dates come from Excel serial numbers with origin `1899-12-30`, or from
  date cells, and become ISO strings without a local time zone.
- A series request returns only the requested series, even though it reads
  whole spreadsheets.
- Parsing code lives in modules whose names end in `-parse`, so the 90 percent
  coverage threshold applies to them.

### Errors

The read fails with these tagged errors, all defined with `Schema`:

| Error                 | Cause                                                             |
| --------------------- | ----------------------------------------------------------------- |
| `InvalidRequest`      | Input fails schema decoding                                       |
| `CatalogueNotFound`   | The Time Series Directory has no series for the catalogue number  |
| `TableNotFound`       | Requested table numbers match no table title                      |
| `SeriesNotFound`      | The Time Series Directory has no record of one or more series IDs |
| `WorkbookLayoutError` | A spreadsheet sheet does not have the ABS time series layout      |
| `HttpClientError`     | Network or HTTP failure, from Effect                              |

`src/` has no `throw`, `try`, or `Effect.orDie`, as the project lint rules
require.

### Command-Line Tool

- The tool adds the noun `abs` and the verb `get`: `ausecon abs get`.
- `get` takes `--catalogue <catalogue number>`, a repeatable `--table <table
  number>`, a repeatable `--series <series ID>`, `--format csv|json`, and
  `--no-metadata`. `--table` needs `--catalogue`. `--catalogue` and `--series`
  exclude each other, and the user must pass one of them.
- Data goes to stdout. Errors go to stderr with a next step. The CSV output has
  a header row and the observation fields in table order. The JSON output is
  one array, pretty-printed only when stdout is a terminal.
- The tool exits with 0 on success and 2 on a usage error. It exits with 3
  when data is not found, 4 on a network or HTTP error, and 1 otherwise.
- The tool provides a fetch-based `HttpClient` layer from Effect.
- Help text leads with examples. Completions come from `effect/cli`.

### Release

- Both packages ship at version 0.1.0. The `CHANGELOG.md` file records the
  release.
- The CI release workflow publishes both packages with provenance after the
  npm setup in the hand-off completes.

## Testing Decisions

- A good test drives public behaviour and checks output. It does not import
  internal modules or assert on call order.
- The library has one test seam. Tests call the public read function with an
  `HttpClient` layer that serves recorded fixtures for each URL. A request
  for an unrecorded URL fails the test.
- The tool has one test seam. Tests run the command in process with
  `Command.runWith` and the existing `CliTestLayer`, plus the same fixture
  `HttpClient` layer. They assert on stdout, stderr, and exit code.
- The existing tool test of `--version` and the workbook layout test of
  `634501.xlsx` are the prior art.
- Fixtures hold recorded ABS responses in `packages/*/test/fixtures/`. They
  include the Time Series Directory pages for the Wage Price Index (`6345.0`)
  with `634501.xlsx`, and `sid` responses for known and unknown series IDs.
  They also include titles with `Table 001`, `X28`, `021_MTH`, an appendix,
  and a multi-number title. Pick these from the October 2026 crawl results.
- Library tests cover each user story from 1 to 29 that does not need a live
  endpoint. Tool tests cover stories 30 to 41.
- The live test project, enabled by `AUSECON_LIVE=1`, reads one catalogue
  number with one table and one series ID from the real ABS endpoints with a
  fetch-based `HttpClient`. The weekly CI job runs it.
- Coverage must reach 85 percent overall and 90 percent for `-parse` modules.

## Out of Scope

- All RBA data. v0.2 ports `readrba`.
- Release selection by date, and any release other than the latest.
- Local caching of spreadsheets or results.
- Reading local spreadsheet files or arbitrary spreadsheet URLs.
- `.xls` spreadsheets and the `.xls` fallback.
- Data cubes, Labour Force helpers, and the `readabs` convenience readers,
  such as `read_cpi()`.
- The ABS Data API (SDMX).
- A Promise-based wrapper of the library.
- Search, browse, and interactive or full-screen terminal modes.
- Single-file binaries.
- Reading tables whose titles have no table number, by table number.

## Further Notes

- ADR 0005 records the local table number matching and its reasons.
- The October 2026 crawl of the whole Time Series Directory found 48
  catalogue numbers, 103,466 series IDs, and 998 table titles. The
  `CatalogueNumber` and `SeriesId` patterns matched every real value. The
  `TableNumber` pattern now matches every extracted table number.
- A large catalogue number, such as Labour Force (`6202.0`), has more than 100
  Time Series Directory pages. A user who needs a few tables should pass table
  numbers or series IDs. The `--help` text says this.
- The ABS describes catalogue numbers as previously used. Series ID requests
  keep working if catalogue number queries stop.
