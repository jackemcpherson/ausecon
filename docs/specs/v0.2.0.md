# V0.2.0: Deepen the Core Interface

This spec defines the second release of `@ausecon/core` and the `ausecon`
command-line tool. It changes the public interface of the library while the
project has few users. Later releases can then add sources without reshaping
it. The v0.1.0 spec planned `readrba` for v0.2. That work moves to v0.3.0.

The architecture review of 27 October 2026 found the friction this spec
removes. Its six candidates and its list of smaller cuts are all in scope.

---

## Problem Statement

An analyst who reads the Wage Price Index with `readAbs` gets 73,357
observations. Each one repeats the unit, series type, frequency, table title,
and the other series metadata. The glossary defines a Series as one sequence
of observations, but the library has no Series type. The analyst rebuilds
series by grouping rows. To get a smaller result the analyst passes an option
that changes the return type, which the library expresses with four overloads.

When the ABS website shows a maintenance page, the tool reports a network
error and tells the analyst to check their connection. The library's error
union carries an Effect HTTP error type. A library user and the tool both
match on Effect internals that change between Effect releases.

An analyst who already holds an ABS table on disk cannot parse it. The parser
is private, and it needs a title that only the Time Series Directory knows.

A maintainer who asks which table holds a series in its latest release reads
four files and three table types. The identity of a table differs between the
code, the glossary, and the output. The tool's tests replay ten Time Series
Directory pages and seventeen tables to check CSV quoting. They import the
library's test helpers by relative path.

## Solution

`readAbs` returns a list of Series. Each Series carries its metadata once, the
Table it came from, and its observations as date and value pairs. The option
that turned metadata off, the second observation type, and the overloads go
away. The tool flattens Series into the twelve `readabs` columns for CSV and
writes Series as they are for JSON.

The library names its own failures. Every HTTP outcome becomes a failure the
library defines, with the URL and the cause attached. No Effect HTTP type
leaves the library. A Time Series Directory error document is a Directory
failure, not a network failure, and exits with the code for a fault to report.

One Time Series Directory module owns paging, latest-release selection, the
table that holds a series, table number matching, and the not-found failures.
It returns one Table type and identifies tables by URL inside the module,
because table IDs are not unique.

The table parser becomes public. A caller passes the bytes of one table and
its labels and gets Series back.

The tool gains a reader seam of its own. Its tests hand in Series or a chosen
failure, and one end-to-end test keeps the recorded fixtures. The fixture
helpers move to a private workspace package.

An ADR records that the read returns an array and not a Stream, so later
reviews do not reopen the question.

## User Stories

The stories group by the part of the project they change.

### Library: Series

1. As an analyst, I want one Series per series ID and sheet from `readAbs`,
   so that I do not group observations myself.
2. As an analyst, I want each Series to carry its metadata once, so that I
   read it from one place.
3. As an analyst, I want each Series to name its Table and sheet, so that I
   can trace a value to its source.
4. As an analyst, I want each observation to be a date and a value, so that I
   plot a Series without stripping fields.
5. As an analyst, I want Series and observations in a stable order, so that
   output does not change between runs.
6. As an analyst, I want dates as ISO `YYYY-MM-DD` strings, so that time zones
   never shift a period.
7. As an analyst, I want one branded series ID type on Series and on failures,
   so that I compare them directly.
8. As an analyst, I want `readAbs` to have one signature and no options, so
   that I learn one call.
9. As an analyst, I want a series request to return only the requested Series,
   so that whole tables do not leak in.
10. As a library user, I want the package to export only the public interface,
    so that internals do not become my dependencies.
11. As a library user, I want the names Series, Table, and Observation to match
    the glossary, so that code and docs agree.

### Library: Failures

12. As a library user, I want every failure to be a type the library defines,
    so that an Effect release never changes my match.
13. As a library user, I want an ABS failure to carry the URL, status, and
    cause, so that I can diagnose it.
14. As a library user, I want a Directory error document to fail as a Directory
    failure, so that I do not blame my network.
15. As a library user, I want a bad table layout to name the table ID, sheet,
    and reason, so that I can report it.
16. As a library user, I want the not-found failures to keep their v0.1.0
    shape, so that only the HTTP failures change.

### Library: Time Series Directory

17. As an analyst, I want a catalogue number request to read the latest
    release, so that superseded releases never mix in.
18. As an analyst, I want table titles matched locally as ADR 0005 records, so
    that zero padding never matters.
19. As an analyst, I want a series read from the lowest table order of its
    latest release, so that no series appears twice.
20. As an analyst, I want two tables that share a file name to stay apart, so
    that neither carries the other's title.
21. As a maintainer, I want one module to own every Directory rule, so that a
    Directory bug has one home.
22. As a maintainer, I want one Table type and one place that identifies
    tables by URL, so that the identity rule lives once.
23. As a maintainer, I want the glossary to define Table URL, so that the
    vocabulary matches the code.
24. As a maintainer, I want Directory tests to need no `.xlsx` fixture, so that
    Directory logic tests stay small.
25. As a maintainer, I want the page parser and title match to keep their unit
    tests, so that the parse threshold still applies.

### Library: Table Parser

26. As an analyst, I want to parse an ABS table I downloaded myself, so that I
    can work offline.
27. As an analyst, I want to pass the table ID and an optional title, so that
    parsed Series carry the same labels as a read.
28. As an analyst, I want the parser to fail with the same layout failure as a
    read, so that one error path serves both.
29. As a maintainer, I want the read and the public parser to share one
    module, so that a layout fix lands once.

### Tool

30. As a terminal user, I want the same twelve CSV columns in the v0.1.0
    order, so that my scripts keep working.
31. As a terminal user, I want `--no-metadata` to write series ID, date, and
    value as CSV, so that piping stays cheap.
32. As a terminal user, I want `--format json` to write the Series list as
    returned, so that the JSON nests by series.
33. As a terminal user, I want JSON without metadata to keep only series ID
    and observations, so that the two flags compose.
34. As a terminal user, I want an ABS error document to exit 1, so that I do
    not debug my network.
35. As a terminal user, I want an unreachable ABS to exit 4 and name the URL,
    so that I can retry or check the address.
36. As a terminal user, I want missing data to exit 3 as before, so that exit
    codes stay stable.
37. As a terminal user, I want stdout to hold no partial data when a read
    fails, so that a pipe never gets half a CSV.
38. As a maintainer, I want the tool to read through a seam of its own, so that
    its tests need no HTTP fixture.
39. As a maintainer, I want one end-to-end tool test on the recorded release,
    so that the whole path stays covered.
40. As a maintainer, I want the fixture helpers in a private workspace package,
    so that no test imports another package by path.
41. As a maintainer, I want the CSV header to come from a list the tool owns,
    so that a library change cannot alter it silently.

### Decisions and Housekeeping

42. As a maintainer, I want an ADR for the array return, so that future

43. As a maintainer, I want an ADR for library-owned failures that amends ADR

## Implementation Decisions

These decisions follow the glossary and the decisions in `docs/adr/`. The
maintainer accepted three choices. The tool gets a reader seam of its own plus
a private fixture package. The read returns an array, recorded in an ADR. The
new types take the glossary names Series, Table, and Observation, unqualified.

### Series, Table, and Observation

- `readAbs` returns an Effect that yields a read-only array of Series. It takes
  one argument, the request. The release deletes the options argument, the
  metadata option, the second observation type, and the four overloads.
- A Series has these fields, in this order:

  | Field               | Source                                       |
  | ------------------- | -------------------------------------------- |
  | `seriesId`          | Row `Series ID`, as the branded series ID    |
  | `seriesDescription` | Spreadsheet row 1                            |
  | `unit`              | Row `Unit`                                   |
  | `seriesType`        | Row `Series Type`                            |
  | `dataType`          | Row `Data Type`                              |
  | `frequency`         | Row `Frequency`                              |
  | `collectionMonth`   | Row `Collection Month`                       |
  | `table`             | The Table the Series was read from           |
  | `sheet`             | Worksheet name, such as `Data1`              |
  | `observations`      | The observations of the Series, in row order |

- A Table has `tableId` and an optional `tableTitle`. It carries no URL: no
  public consumer needs one, and the parser cannot supply one. Table IDs are
  not unique, so the Directory module identifies tables by URL internally, and
  the Table documentation says so. The Time Series Directory always supplies a
  title. The public parser may not have one.
- An Observation has `date`, an ISO `YYYY-MM-DD` string, and `value`, a
  number. Blank and text value cells produce no observation, as in v0.1.0.
- Series come in table order, then sheet order, then column order. A series
  request returns only the Series whose table URL and series ID the Directory
  named. The filter runs after parsing, inside the read. The download module
  takes no predicate.
- The series ID on a Series is the branded `SeriesId`, the same type as in
  `SeriesNotFound`.
- The public exports are: `readAbs`, the parser, `AbsRequest`, `ReadAbsError`,
  `Series`, `Table`, `Observation`, `CatalogueNumber`, `SeriesId`,
  `TableNumber`, `TableId`, and the failures. The package stops exporting the
  decoded request schemas.
- The Series, Table, and Observation names carry no source prefix. Their
  metadata fields are ABS fields. When v0.3.0 adds the RBA, that spec decides
  whether metadata becomes per-source.

### Failures

- `ReadAbsError` is a union of library-defined tagged errors only. No
  `effect/http` type appears in it.
- `AbsUnavailable` replaces `HttpClientError`. The library fails with it when
  a request to the ABS gets no response or a status outside 2xx. It carries
  the URL, the status if the ABS answered, and the cause as text.
- `TimeSeriesDirectoryError` is the failure for a Directory response that is
  not a series index: an error document, malformed XML, or an unexpected
  layout. It carries the URL and the reason. It replaces the v0.1.0 practice
  of dressing this case as an HTTP decode error, which ADR 0006 recorded.
- `TableLayoutError` is the new name of `WorkbookLayoutError`. The glossary
  avoids "workbook". It keeps the same fields: table ID, optional sheet, and
  reason.
- `InvalidRequest`, `CatalogueNotFound`, `TableNotFound`, and `SeriesNotFound`
  keep their names and fields.
- The HTTP module maps Effect's client errors to `AbsUnavailable` at the point
  of each request. Effect's error type stays inside the library.
- A new ADR records that the library owns its failures and amends the last
  paragraph of ADR 0006.

### Time Series Directory

- One module owns the Directory. Its interface answers two questions. First,
  the tables of a catalogue number, limited to optional table numbers. Second,
  the table and Directory row of a series ID. It fails with
  `CatalogueNotFound`, `TableNotFound`, `AbsUnavailable`, and
  `TimeSeriesDirectoryError`.
- Inside it: page fetching with `NumPages` from page 1 under the concurrency
  limit. The latest `ProductReleaseDate` per table URL. Rows with an empty
  table URL dropped. The lowest `TableOrder` row of the latest release for a
  series ID. The table ID derived from the file name of the table URL. Title
  matching as ADR 0005 records.
- The module returns one Table type. The orchestrating read module no longer
  calls latest-release helpers, builds string keys, or sorts by table order.
- The Directory page parser and the title match stay as internal seams with
  their own unit tests. The page parser keeps the `-parse` suffix so the 90
  percent coverage threshold applies. The coverage pattern must match any
  renamed module.
- The Directory row type keeps only the fields the read uses. Browse and
  search are out of scope, and adding fields later is internal.
- The glossary gains the term Table URL and notes under Table ID that two
  tables can share a table ID.

### Table Parser

- The library exports the parser the read uses. It takes the bytes of one
  `.xlsx` table and a Table, with the table ID required and the title
  optional. It returns the Series of the table or fails with
  `TableLayoutError`.
- The parser keeps the ABS layout as module constants. It takes no layout
  parameter and shares no cell helpers, because no second layout exists yet.
  One adapter is a hypothetical seam.
- The parser is the second `-parse` module under the 90 percent threshold.

### Download

- The download module takes Tables and returns Series per table. It keeps the
  space-to-plus URL fix, the project User-Agent, redirects, and one download
  per distinct table URL.
- One named concurrency limit serves Directory pages and table downloads. The
  separate series lookup limit folds into the same constant.

### Command-Line Tool

- The tool defines a reader service private to its package. The live adapter
  calls `readAbs`, and the entry point provides it. Tests provide a fake that
  returns Series or fails with a chosen `ReadAbsError`. The live adapter stays
  a one-line layer, so the entry point, which coverage excludes, holds nothing
  to test.
- The tool owns the twelve CSV columns as a literal list in the v0.1.0 order.
  The order is table ID, sheet, table title, date, series description, value,
  series type, data type, collection month, frequency, series ID, unit. An
  absent table title writes an empty field. A flatten step turns Series into
  rows.
- `--no-metadata` keeps its name and becomes the one name for the concept in
  the tool. With CSV it writes series ID, date, and value. With JSON it writes
  each Series with only its series ID and observations.
- `--format json` writes the Series list as the library returns it, indented
  only for a terminal.
- Exit codes: 0 on success and 2 on a usage error. Exit 3 for
  `CatalogueNotFound`, `TableNotFound`, and `SeriesNotFound`. Exit 4 for
  `AbsUnavailable`. Exit 1 for `TimeSeriesDirectoryError`, `TableLayoutError`,
  and any unexpected failure.
- The next step for `AbsUnavailable` depends on whether a status is present.
  Without one, check the network. With one, try later or report that the data
  moved. The next step for `TimeSeriesDirectoryError` and `TableLayoutError`
  is to report the fault.
- The tool no longer matches Effect HTTP reason tags.
- The tool holds stdout until the command finishes, as in v0.1.0. The read
  returns an array, so streaming output is not a goal.
- The validation that runs the request builder twice stays. It is a known
  `effect/cli` limit, and the code comment explains it.
- Error copy that names the ABS stays. A source parameter waits for the RBA
  verb.

### Fixtures and Workspace

- The fixture HTTP client, the recorded responses, and the synthetic table
  builder move to a private workspace package that both test suites import by
  name. The package is never published. It sits under the workspace glob, so
  the coverage include pattern must leave it out.
- The recorded fixture files move with the helpers.
- The release deletes the test that opens a fixture with SheetJS directly.
- The Vite configuration drops the alias to a `promise` entry that does not
  exist.

### Architecture Decision Records

- A new ADR records that `readAbs` returns an array, not a Stream. A Stream is
  a second concept for every caller. A consumer builds a Stream from an array
  in one call. The Series shape removes repeated metadata. The tool keeps
  all-or-nothing stdout.
- A new ADR records that the library owns its failures, and amends ADR 0006 so
  that a Directory error document fails with `TimeSeriesDirectoryError`.

### Documentation and Release

- The core package guide shows the Series shape, the public parser, and the
  new failures. The tool guide shows the JSON shape and the exit codes.
- The changelog records 0.2.0 with a Changed section and an Added section. The
  Changed section covers the return type, the failures, the JSON output, and
  the removed option. The Added section covers the parser.
- Both packages ship at version 0.2.0.

## Testing Decisions

- A good test drives public behaviour and checks output. It does not import
  internal modules or assert on call order.
- The library keeps one test seam: tests call `readAbs` with an `HttpClient`
  layer that serves recorded fixtures by URL. Tests for the Series shape, the
  Directory module, and the failures all drive this seam. Directory tests
  serve recorded Directory pages and one synthetic table at every table URL,
  as the table number tests already do.
- Parser tests pass bytes directly: recorded tables for the shape, synthetic
  tables for layout failures.
- The Directory page parser and the title match keep their unit tests as
  internal seams.
- The tool has two seams. Tool tests run the command in process with the
  existing test layer and a fake reader. The fake returns hand-built Series or
  a chosen failure, and the tests assert on stdout, stderr, and exit code. One
  end-to-end test runs the recorded Wage Price Index release through the
  fixture `HttpClient`. It asserts the header, the first row, and the row
  count.
- Each failure type has a tool test that checks its exit code and next step.
  A Directory error document must exit 1, not 4.
- Prior art: the catalogue, series, table number, and synthetic release tests
  in the library, and the `abs get` tests in the tool.
- Coverage must reach 85 percent overall and 90 percent for the two `-parse`
  modules. Any rename updates the coverage pattern.
- The live test keeps reading one table number and one series ID from the
  real ABS and asserts on Series.

## Out of Scope

- All RBA data. `readrba` moves to v0.3.0.
- A Stream-returning read, and streaming output in the tool.
- Browse and search over the Time Series Directory, and the latest-date
  check. The Directory row type does not keep the extra metadata for them.
- A tool verb for local files. The parser is library-only in this release.
- A layout parameter or shared cell helpers for the parser.
- A source parameter for the tool's error copy.
- Release selection by date, caching, `.xls` tables, data cubes, the ABS Data
  API, and a Promise wrapper, as in v0.1.0.
- Reading tables whose titles have no table number, by table number.

## Further Notes

- The v0.1.0 spec stays as a record. This spec supersedes its Observation
  Shape section and its metadata option.
- Memory: the Series shape stores each metadata string once per Series rather
  than once per observation. The JSON output shrinks accordingly. CSV output
  keeps its size.
- The breaking changes are the return type of `readAbs`, the removed options
  argument, and the removed `ObservationValue` and decoded request exports.
  Also the renamed `WorkbookLayoutError`, the replaced `HttpClientError`, and
  the JSON output shape of the tool. CSV output and exit codes 2 and 3 do not
  change.
