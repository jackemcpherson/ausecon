# V0.3.0: Read RBA Statistical Tables

This spec defines the third release of `@ausecon/core` and the `ausecon`
command-line tool. It adds RBA statistical tables, one Series shape for both
publishers, and a first search over a series index. The terminal interface
follows in v0.4.0 and builds on all three.

ADR 0009 sets the goal: the easiest way to work with Australian economic
data. The `readrba` package sets the coverage benchmark, not the design. The
research note `docs/research/abs-rba-data-access.md` holds the evidence for
the data access choices below.

---

## Problem Statement

An analyst who wants the cash rate target next to the Wage Price Index cannot
get it from `ausecon`. The tool reads only ABS data. The RBA publishes the
cash rate, interest rates, exchange rates, and credit aggregates as
statistical tables, and the analyst downloads each spreadsheet by hand.

The analyst also has to know where a series lives. A series ID such as
`FIRMMCRTD` names a series, but nothing tells the analyst that it sits in
table F1. The RBA has no service that maps a series ID to its table, and no
API.

The analyst cannot find a series without its ID. Neither the ABS nor the RBA
lets a client list its series cheaply. So the tool has nothing to search.

Last, the library's `Series` type is ABS-shaped. It has `collectionMonth` and
`dataType`, which RBA series lack. It has no publication date or source,
which RBA series carry.

## Solution

The library gains `readRba`. It reads current RBA statistical tables by RBA
table number, or series by series ID, and returns the same Series union that
`readAbs` returns. Each Series names its publisher.

A series index ships with the library (ADR 0010). It lists every series ID in
the current tables, with its description, unit, frequency, series type, and
table. A read finds tables through it, and a search reads it. A script builds
the index before each release.

The tool gains three commands:

- `ausecon get` reads series IDs from either publisher in one call.
- `ausecon rba get` reads RBA statistical tables by RBA table number.
- `ausecon search` finds RBA series by words in their descriptions.

## User Stories

The stories group by the part of the project they change.

### Library: RBA Reads

1. As an analyst, I want to read a statistical table by RBA table number, so
   that I skip the spreadsheet.
2. As an analyst, I want to read several RBA table numbers in one call, so that
   I build one dataset from several tables.
3. As an analyst, I want to read RBA series by series ID, so that I do not need
   to know which table holds them.
4. As an analyst, I want to read the cash rate target by its series ID,
   `FIRMMCRTD`, so that I need no special function for it.
5. As an analyst, I want RBA table numbers matched without regard to case, so
   that `f1.1` finds F1.1.
6. As an analyst, I want RBA series IDs matched without regard to case, so that
   a lower-case ID still reads.
7. As an analyst, I want `.xls` current tables read as well as `.xlsx`, so that
   the daily exchange rates in F11.1 are not missing.
8. As an analyst, I want each RBA Series to carry the table's metadata rows, so
   that I can label a chart.
9. As an analyst, I want observation dates as ISO strings, so that RBA and ABS
   dates sort and join the same way.
10. As an analyst, I want blank cells left out of the observations, so that a
    series holds only published values.
11. As an analyst, I want a Frequency of "See notes" kept as the RBA wrote it,
    so that the library does not guess.
12. As an analyst, I want the Notes and "Use of Expert Judgement" sheets
    ignored, so that only data reaches my Series.
13. As an analyst, I want the read to finish every download before it returns,
    so that I never get half a result (ADR 0008).

### Library: One Series Shape

14. As an analyst, I want ABS and RBA series in one Series union, so that one
    function handles both.
15. As an analyst, I want each Series to name its publisher, so that I can tell
    an ABS series from an RBA one.
16. As an analyst, I want the shared fields named the same on both, so that I
    read them without checking the publisher.
17. As an analyst, I want each publisher's own fields on its own member, so that
    no field holds a filler value.
18. As an analyst, I want an RBA Series to name its source, so that I see when
    the RBA republishes ABS data.

### Library: Failures

19. As a developer, I want `readRba` to fail only with library errors, so that
    Effect releases cannot break my matches (ADR 0007).
20. As a developer, I want `RbaUnavailable` when the RBA does not answer or
    answers outside 2xx, so that I can retry.
21. As a developer, I want `RbaTableNotFound` when no current table has the RBA
    table number, so that I can correct the request.
22. As a developer, I want `RbaTableNotFound` when a table URL from the index
    answers 404, so that a stale index fails with a clear cause.
23. As a developer, I want `RbaSeriesNotFound` to name every missing series ID,
    so that I fix them all at once.
24. As a developer, I want `RbaTableLayoutError` when a table does not have the
    RBA layout, so that I know the RBA changed the file.
25. As a developer, I want `RbaTableLayoutError` when I read a table that the
    index lists as unreadable, so that I get the reason without a download.
26. As a developer, I want `InvalidRequest` shared with `readAbs`, so that I
    handle bad input one way.

### Library: Series Index and Search

27. As an analyst, I want to search RBA series by words, so that I find a series
    without knowing its ID.
28. As an analyst, I want every word to match, in any order and any case, so
    that more words narrow the results.
29. As an analyst, I want words matched against the series ID, description,
    title, and table title, so that "cash rate target" finds `FIRMMCRTD`.
30. As an analyst, I want each result to show its ID, description, unit,
    frequency, and table, so that I can pick one.
31. As an analyst, I want to cap the number of results, so that a broad word
    does not flood my screen.
32. As an analyst, I want search to work offline, so that I can browse on a
    train.
33. As a maintainer, I want the index to record each table's last-modified date,
    so that a later release can show what changed.
34. As a maintainer, I want the index to list each table that failed to parse
    and why, so that the gaps are visible.

### Tool

35. As an analyst, I want `ausecon get` to read series IDs from both publishers
    in one call, so that I build a mixed dataset in one step.
36. As an analyst, I want `ausecon get` to infer each publisher from the series

## Implementation Decisions

These decisions follow the glossary and ADR 0007 to ADR 0010. The maintainer
settled them in a design review on 29 October 2026.

### Series Union

- `Series` becomes a union of `AbsSeries` and `RbaSeries`, tagged by a
  `publisher` field with the values `ABS` and `RBA`.
- Both members share `seriesId`, `description`, `unit`, `frequency`,
  `seriesType`, `table`, and `observations`. `Observation` does not change.
- `AbsSeries` adds `dataType`, `collectionMonth`, and `sheet`, and keeps its
  current `table` shape.
- `RbaSeries` adds `title`, `source`, and `publicationDate`, an ISO date. Its
  `table` holds the RBA table number and the table title.
- The ABS `seriesDescription` field becomes `description`. This breaks the
  v0.2.0 type and the JSON output. The ABS CSV columns do not change.
- `SeriesId` widens to accept RBA series IDs. The publisher comes from the ID
  pattern: an ABS ID matches the ABS pattern, and every other valid ID is an RBA
  ID. A prefix of `abs:` or `rba:` overrides the pattern.

### RBA Read

- `readRba` takes an `RbaRequest`, a tagged enum like `AbsRequest`. The `Table`
  variant holds RBA table numbers. The `Series` variant holds series IDs. The
  read upper-cases and decodes both.
- It returns an `Effect` that yields a read-only array of `Series` and needs an
  `HttpClient`, as `readAbs` does.
- It finds every table through the series index. It downloads each needed table
  once, with the same concurrency limit and user agent as the ABS download.
- A series ID request returns only the requested series, in request order.
- `readAbs` keeps its signature. The library adds no combined read in this
  release. The tool splits mixed series IDs between the two reads.

### RBA Table Parser

- The parser reads the Data sheet only. It finds the label rows by the text in
  column A: Title, Description, Frequency, Type, Units, Source, Publication
  date, and Series ID. It does not rely on fixed row numbers.
- Observations start on the first row after Series ID. Dates arrive as Excel
  serial numbers or as text, and the parser writes both as ISO dates.
- The parser handles `.xlsx` and `.xls` through the existing SheetJS reader. ADR
  0003 does not limit the project to `.xlsx`. The v0.1.0 spec did.
- A sheet without the label rows or a Series ID row fails with
  `RbaTableLayoutError`, which carries the table URL and the reason.
- The parser stays internal. The library does not export it in this release.

### Failures

- `ReadRbaError` is the union of `RbaUnavailable`, `RbaTableNotFound`,
  `RbaSeriesNotFound`, `RbaTableLayoutError`, and `InvalidRequest`.
- The HTTP module maps Effect client errors at each request, as ADR 0007
  requires. A 404 on a table URL maps to `RbaTableNotFound`. Every other status
  outside 2xx maps to `RbaUnavailable`.
- `RbaTableNotFound` and `RbaSeriesNotFound` say that the series index may be
  out of date when the cause could be a stale index.

### Series Index

- The index build writes generated data into the library (ADR 0010). It holds,
  per series, the series ID, title, description, unit, frequency, series type,
  and RBA table number. Per table, it holds the RBA table number, title, URL,
  and last-modified date. It also lists unreadable tables with the reason.
- The library exports `searchSeries`, a pure function over the index. It takes
  the words and an optional limit. It returns index entries, not Series, so a
  search makes no request.
- A match needs every word inside the series ID, title, description, or table
  title, in any case. Results keep index order, which is table order and then
  column order.
- The index records each table's `Last-Modified` header. Nothing reads the date
  in this release.

### Index Build

- `bun run rba:index` runs a Bun script in its own private workspace package. It
  may use Node and Bun APIs and an HTML parser, because it ships nothing at run
  time.
- It reads the current tables page, keeps each Excel link with its title and RBA
  table number, and downloads every table. It parses each table with the
  library's RBA parser.
- It writes the generated index into the library and formats it with the project
  formatter.
- The build fails when the unreadable tables differ from those in the committed
  index. An explicit flag accepts the new set.

### Command-Line Tool

- `ausecon get <series id...>` reads series IDs from both publishers. It groups
  the IDs by publisher, runs both reads, and writes the results in request
  order. Any failure fails the command with no stdout (ADR 0008).
- `ausecon rba get <rba table number...>` reads RBA statistical tables.
- `ausecon search <word...>` searches the series index. `--limit` defaults to
  20. A terminal gets aligned columns. A pipe gets CSV, or JSON with `--format
  json`. An empty result exits 0 with a message on stderr.
- `abs get --series` keeps working for this release. It writes a note on stderr
  that names `ausecon get`. The next release removes it.
- `--format` and `--no-metadata` work on `get` and `rba get` as they do on `abs
  get`.
- CSV columns: `abs get` keeps its 12 `readabs` columns. The shared columns
  are the 8 of those that an RBA series also fills, in the same order:
  `tableTitle`, `date`, `seriesDescription`, `value`, `seriesType`,
  `frequency`, `seriesId`, and `unit`. `rba get` writes the shared columns,
  then `title`, `source`, and `publicationDate`. `get` writes `publisher` and
  the shared columns, so one header fits both publishers.
- The reader seam gains the RBA read and the search. Each RBA failure maps to
  the exit code of its ABS counterpart, with RBA wording on stderr.

### Fixtures and Workspace

- `@ausecon/testkit` gains recorded RBA tables: F1 for the cash rate, F1.1, one
  `.xls` table, and one table with a "See notes" frequency. It also gains the
  current tables page and synthetic tables for layout failures.
- The index build gets its own private workspace package with its own tests.

### Documentation and Release

- Both package guides document `readRba`, `searchSeries`, the Series union, and
  the three commands. They state that a browser needs a proxy.
- Both package guides carry "Source: Reserve Bank of Australia" and state that
  the RBA does not endorse the project.
- Both packages release as 0.3.0. The changelog lists the breaking changes.

## Testing Decisions

- A good test drives public behaviour and checks output. It does not import
  internal modules or assert on call order.
- `readRba` tests use the existing library seam: an `HttpClient` layer that
  serves recorded fixtures by URL. They cover the Series shape, the `.xls` path,
  and the index lookup. They also cover a 404 on a table URL, a missing series
  ID, a "See notes" frequency, and each failure. Synthetic tables cover layout
  failures. The RBA parser has no seam of its own.
- `searchSeries` tests call the function with no network and assert on the
  entries it returns: all-words matching, case, limit, and empty results.
- Index build tests run the script's build step against a fixture `HttpClient`
  with the recorded current tables page and a few tables. They assert on the
  generated index, including the unreadable list and the failure when that list
  changes.
- Tool tests run commands in process with the existing test layer and a fake
  reader. They cover `get` with mixed IDs and prefixes, `rba get`, `search`, the
  `--series` alias note, and each RBA failure's exit code and next step. One
  end-to-end test runs the recorded F1 table through the fixture `HttpClient`.
- The live test (`AUSECON_LIVE=1`) reads one RBA table and `FIRMMCRTD` from the
  real RBA.
- Prior art: the `readAbs` catalogue, series, and synthetic release tests in the
  library, and the `abs get` tests in the tool.
- Coverage must reach 85 percent overall and 90 percent for every `-parse`
  module, including the RBA parser.

## Out of Scope

- Historical tables. They are mostly `.xls`, and `readrba` patches several of
  them with invented metadata.
- Statement on Monetary Policy forecasts.
- An ABS series index, and so ABS search. A later release measures its size and
  decides where it lives.
- The terminal interface. v0.4.0 builds it on this release.
- The ABS Data API (SDMX). The research note keeps it for a later source or a
  browser build.
- A scheduled index refresh, a combined library read, ranked or fuzzy search,
  and a "what's new" view.
- Release selection by date, caching, data cubes, and a Promise wrapper, as in
  v0.2.0.

## Further Notes

- Coverage against `readrba`: `read_rba` by table and by series ID, and
  `read_cashrate`, which becomes a plain series ID read. `browse_rba_series` and
  `browse_rba_tables` become `search`. Historical tables, `read_forecasts`, and
  `read_rba_local` wait for later releases.
- The research note found that the RBA CSV files round values to the digits
  shown, and that 22 of them are not UTF-8. The spreadsheets are the only exact
  source.
- The breaking changes are the Series union, the renamed `description` field,
  the JSON output shape, and the widened `SeriesId`. `abs get` CSV output and
  its exit codes do not change.
